# 后端开发规范 Skill - 演示汇报说明

## 概述

`backend-development-standard` 是后端业务开发的项目级规范 Skill。

它的作用不是替代 Java/Spring Boot 通用开发经验，而是把当前脚手架工程里的后端边界、目录放置、命名约定、测试留痕和收尾检查统一起来，避免 AI 在不同任务里出现“今天一种结构、明天一种结构”的问题。

当任务涉及 `code/backend/` 下的 Java 后端代码时，应优先触发该 Skill，并先阅读 `code/backend/AGENTS.md`。

## 核心能力

- 判断后端代码应落在哪个 Maven 模块：`backend-api`、`backend-core`、`backend-data` 或 `aldemo`。
- 约束业务代码默认落在 `aldemo`，避免过早抽取到公共模块。
- 按 `docs/需求/模块总表.md` 中登记的模块编码建立业务子目录，例如 `部门管理 = dept`。
- 统一 controller、service、repository、mapper、request、response、vo、dataobject、mapper XML 和测试报告的目录层级。
- 保持现有返回结构、异常风格、注释风格和测试方式，不主动扩大重构范围。
- 要求完成后补充必要验证，并在涉及需求、数据库或规范变化时联动对应记录文档。

## 推荐目录示例

以 `部门管理 = dept` 为例，业务应用层默认按模块编码放置：

```text
controller/dept/
service/dept/
service/dept/impl/
repository/dept/
repository/dept/impl/
mapper/dept/
model/request/dept/
model/response/dept/
model/vo/dept/
model/dataobject/dept/
resources/mapper/dept/
test/java/.../app/dept/
test/resources/test-report/dept/
```

模块编码必须优先来自 `docs/需求/模块总表.md`，不要在需求文档、后端包名和 DataSQL 目录之间各起一套名字。

## 工作流程演示

1. 识别任务是否修改 `code/backend/`。
2. 读取根目录 `AGENTS.md` 和 `code/backend/AGENTS.md`。
3. 如果任务来自具体需求，先确认 `docs/需求/模块总表.md` 中是否已有模块登记。
4. 判断代码归属 Maven 模块，业务代码默认放入 `aldemo`。
5. 按模块编码建立或复用业务子目录。
6. 阅读相邻代码，沿用现有返回、异常、Mapper、DTO 和测试风格。
7. 实现最小必要改动。
8. 运行必要验证，并记录无法执行的原因。
9. 命中需求、数据库或规范留痕场景时，联动 `requirement-implementation-tracking`、`database-schema-standard` 和 `change-tracking`。

## 典型场景

- 新增一个业务接口，例如部门分页查询、字典维护、用户启停用。
- 修改已有 controller/service/repository/mapper 逻辑。
- 新增 request、response、vo、dataobject 等模型对象。
- 新增或调整后端测试、测试报告和接口回归说明。
- 在业务实现过程中需要确认代码应放到哪个模块、哪个包名、哪个测试目录。

## 与其他 Skill 的联动

- `requirement-implementation-tracking`：负责先拆需求模块、登记模块编码，再推动后端目录按模块编码落位。
- `database-schema-standard`：涉及表、字段、索引、Mapper SQL 或 DataSQL 留痕时必须联动。
- `change-tracking`：涉及需求、架构、规范、跨模块影响或可追溯 Bug 修复时补变更记录。
- `jdk-maven-matrix`：需要调整 JDK、Maven、Spring Boot、Spring Cloud 等技术基线时联动。

## 禁止事项

- 不要绕过 `code/backend/AGENTS.md` 直接按通用 Spring Boot 习惯写代码。
- 不要把具体业务默认放入 `backend-api`、`backend-core` 或 `backend-data`。
- 不要让同一业务模块在需求中叫“部门”、代码里叫 `organization`、DataSQL 里叫“组织管理”。
- 不要只改代码不验证、不留痕。
- 不要为一次小改动顺手做无关大重构。
