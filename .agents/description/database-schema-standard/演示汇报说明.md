# 数据库结构规范 Skill - 演示汇报说明

## 概述

`database-schema-standard` 是当前项目中数据库设计、SQL 变更和 DataSQL 留痕的项目级规范 Skill。

它负责把“表怎么设计、字段怎么命名、SQL 怎么写、数据库变更怎么记录”统一起来，并和需求模块体系保持同一套模块名称和模块编码。

当任务涉及表结构、字段、索引、初始化 SQL、Mapper SQL 或 `code/backend/DataSQL/` 留痕时，应触发该 Skill。

## 核心能力

- 识别当前项目数据库方言，优先读取 `code/backend/*/src/main/resources/application*.yml`、`pom.xml` 和既有 SQL。
- 约束建表、字段、主键、逻辑删除、时间字段、状态字段、索引和注释写法。
- 要求 DataSQL 业务目录名优先来自 `docs/需求/模块总表.md`。
- 维护 `code/backend/DataSQL/业务变更汇总清单.md`。
- 维护 `code/backend/DataSQL/<业务模块>/表设计与变更记录.md`，作为 SQL、字段、索引和变更流水的正式来源。
- 与 `docs/需求/模块/<模块>/数据库留痕索引.md` 双向引用，但不在需求目录重复维护完整 SQL。

## DataSQL 推荐结构

```text
code/backend/DataSQL/
├── 业务变更汇总清单.md
└── 字典管理/
    └── 表设计与变更记录.md
```

如果 `docs/需求/模块总表.md` 中登记为：

```text
部门管理 | dept | dept | 部门管理
```

则后端 DataSQL 目录应使用同一业务目录名，不要另起 `organization`、`org` 或“组织管理”。

## 工作流程演示

1. 判断是否涉及数据库结构、SQL 或 Mapper SQL。
2. 读取 `code/backend/AGENTS.md` 和 `database-schema-standard/SKILL.md`。
3. 确认数据库方言和既有 SQL 风格。
4. 如果来自业务需求，先读取 `docs/需求/模块总表.md`，确认模块中文名、模块编码和 DataSQL 目录名。
5. 设计或调整表结构、字段、索引和 SQL。
6. 更新 `code/backend/DataSQL/<业务模块>/表设计与变更记录.md`。
7. 更新 `code/backend/DataSQL/业务变更汇总清单.md`。
8. 如果对应需求模块存在，同步更新 `docs/需求/模块/<模块>/数据库留痕索引.md`，只写链接和摘要，不复制完整 SQL。
9. 补充必要验证，例如 SQL 静态检查、Mapper 测试、单元测试或说明无法执行的原因。

## 典型场景

- 新增业务表或调整已有表字段。
- 新增索引、唯一约束、逻辑关联或初始化数据。
- 修改 Mapper XML、注解 SQL 或复杂查询。
- 根据需求模块补齐数据库影响说明。
- 检查 DataSQL 目录是否和需求模块、后端包名保持一致。

## 与其他 Skill 的联动

- `requirement-implementation-tracking`：负责模块拆分和 `模块总表.md`，数据库目录命名优先服从该总表。
- `backend-development-standard`：涉及 Mapper、Repository、DO、业务代码目录时联动。
- `change-tracking`：数据库结构变更通常需要同步项目级变更记录。

## 禁止事项

- 不要只改 Mapper SQL 或 DDL，不更新 DataSQL 留痕。
- 不要在 `docs/需求/` 里复制一份完整 SQL，造成双源维护。
- 不要绕过 `模块总表.md` 单独给 DataSQL 目录起名。
- 不要在未确认数据库方言时生成特定方言 SQL。
- 不要把数据库变更只寄托在 Git diff 中。
