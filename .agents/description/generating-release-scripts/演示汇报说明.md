# 发布脚本生成 Skill - 演示汇报说明

## 概述

`generating-release-scripts` 是为当前项目生成前端、后端和整体发布脚本的项目级 Skill。

它关注的是“如何把项目可靠地构建、打包、登记、部署”，并通过分层脚本降低不同环境、不同模块发布时的手工错误。

## 核心能力

- 为前端静态资源生成构建和发布脚本。
- 为后端 jar、war、archive 或 Docker 镜像生成打包和发布脚本。
- 支持按 `check-env`、`build-base`、`publish`、`report` 等层次拆分发布流程。
- 生成脚本前检查项目结构、构建命令、产物目录和环境变量。
- 默认加入 dry-run、环境保护、参数校验和执行报告。
- 避免把发布逻辑散落在不可追溯的一次性命令里。

## 工作流程演示

1. 判断用户要发布的是前端、后端、镜像还是完整项目。
2. 读取根目录 `AGENTS.md`，并按需读取 `code/frontend/AGENTS.md` 或 `code/backend/AGENTS.md`。
3. 检查现有构建工具，例如 npm/pnpm、Maven、Dockerfile 或既有脚本。
4. 设计分层脚本：环境检查、基础构建、发布执行、结果报告。
5. 生成可重复执行的脚本和说明。
6. 执行静态检查或 dry-run，确认脚本入口和路径正确。
7. 涉及项目级发布约定变化时，联动 `change-tracking`。

## 典型场景

- 生成前端构建并复制到静态目录的脚本。
- 生成后端 Maven 打包、归档、镜像构建脚本。
- 生成一键发布脚本，但保留 dry-run 和生产环境确认。
- 拆分本地构建、制品登记、远端部署的职责。
- 给交付团队准备可演示、可复跑的发布流程。

## 与其他 Skill 的联动

- `backend-development-standard`：发布后端服务时确认 Maven 模块和产物路径。
- `jdk-maven-matrix`：涉及 Maven/JDK 版本要求时确认兼容矩阵。
- `change-tracking`：新增或调整发布规范时补充项目级变更记录。

## 禁止事项

- 不要生成只有本机能跑、路径写死且无说明的脚本。
- 不要默认直接执行生产部署。
- 不要把构建、上传、部署、报告全部揉成不可维护的一大段命令。
- 不要在未确认产物目录和构建工具前编造发布路径。
