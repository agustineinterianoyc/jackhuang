# JDK 与 Maven 版本矩阵 Skill - 演示汇报说明

## 概述

`jdk-maven-matrix` 是后端技术基线选择的项目级 Skill。

它用于在初始化项目、升级依赖或生成后端脚手架时，统一判断 JDK、Maven、Spring Boot、Spring Cloud、Spring Cloud Alibaba、Nacos、数据库驱动和常用基础依赖的兼容关系。

## 核心能力

- 按目标 JDK 版本给出 Maven 和 Spring Boot 兼容建议。
- 收敛 Spring Cloud 与 Spring Cloud Alibaba 版本。
- 给出 Nacos、MySQL、PostgreSQL、Oracle、达梦、人大金仓、Druid、MyBatis Plus 等常用依赖建议。
- 区分 JDK 8 兼容线和 JDK 21 现代线。
- 在生成或调整后端 `pom.xml` 前提供统一版本来源。
- 帮助避免“JDK 能跑但 Boot/Cloud/Alibaba 不兼容”的隐性问题。

## 工作流程演示

1. 识别任务是否涉及后端技术版本选择。
2. 确认目标 JDK 版本和项目类型。
3. 按矩阵选择 Maven、Spring Boot、Spring Cloud 和 Spring Cloud Alibaba。
4. 根据数据库和中间件需求选择驱动与基础依赖版本。
5. 生成版本建议或用于 `pom.xml` 的版本清单。
6. 如果修改了项目技术基线，联动 `change-tracking` 记录规范变化。

## 典型场景

- 初始化一个新的 Spring Boot 后端工程。
- 判断当前项目是否适合升级到 JDK 21。
- 给微服务项目选择 Spring Cloud 与 Alibaba 版本。
- 生成支持多数据库驱动的后端依赖基线。
- 排查依赖版本不匹配导致的构建或启动问题。

## 与其他 Skill 的联动

- `project-init`：初始化脚手架时优先使用该矩阵收敛后端技术基线。
- `backend-development-standard`：后端开发中涉及依赖升级时联动。
- `generating-release-scripts`：发布脚本需要校验 JDK/Maven 环境时可引用该矩阵。
- `change-tracking`：技术基线变更属于规范类变更，需要留痕。

## 禁止事项

- 不要凭印象混搭 Spring Boot、Spring Cloud 和 Spring Cloud Alibaba。
- 不要在未确认 JDK 版本时直接生成父 POM。
- 不要把临时依赖升级当成无影响的小改。
- 不要忽略 Maven 版本与 JDK、插件生态的兼容性。
