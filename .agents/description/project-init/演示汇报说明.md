# 项目初始化 Skill - 演示汇报说明

## 概述

`project-init` 是把当前示例脚手架收敛为真实项目的项目级 Skill。

它适用于正式开发开始前的初始化阶段，重点是清理演示残留、确认项目事实、替换项目命名、收敛包名模块名，并同步更新 AI 约束文档和变更记录。

## 核心能力

- 扫描脚手架中的示例命名、演示页面、临时配置和待替换标识。
- 分批收集项目事实，例如项目中文名、英文名、包名、前端应用名、后端服务名、数据库和 JDK 版本。
- 保护项目级规范资产，例如整个 `.agents/skills/`、`.agents/description/`、`AGENTS.md`、`docs/规范/AI开发SOP.md`、`docs/规范/` 等。
- 调用初始化脚本批量替换可确定的配置和标识。
- 按需联动 `jdk-maven-matrix` 选择后端版本基线。
- 更新初始化过程中的变更记录，避免初始化动作不可追溯。
- 在归档或重建 `docs/变更记录/` 时，保留各分类文档中的模板示例段落，而不是重建成空白壳文件。

## 工作流程演示

1. 判断任务是否是在把脚手架初始化成真实项目。
2. 读取 `project-init/SKILL.md` 和根目录 `AGENTS.md`。
3. 扫描项目事实和演示残留。
4. 分批确认需要替换的项目标识。
5. 按保护清单避开不能清理的规范资产。
6. 执行最小范围替换和清理。
7. 运行必要验证，例如搜索残留、构建检查或配置检查。
8. 更新 AGENTS、SOP 和变更记录。

## 典型场景

- 从 `process-ex` 脚手架改成真实业务项目。
- 替换 Java 包名、Maven artifact、服务名、前端标题和应用标识。
- 清理 demo 页面、示例接口、示例 SQL 或示例配置。
- 初始化时确认 JDK/Maven/Spring Boot 技术基线。
- 将初始化后的约束同步给后续 AI 开发流程。

## 与其他 Skill 的联动

- `jdk-maven-matrix`：确认后端版本基线。
- `backend-development-standard`：初始化后端模块和包结构时遵守。
- `database-schema-standard`：初始化数据库脚本或 DataSQL 目录时遵守。
- `change-tracking`：初始化过程通常属于项目级变更，需要留痕。

## 禁止事项

- 不要把项目级 Skill、AGENTS、SOP、变更记录等规范资产当成演示残留清理掉。
- 不要因为新增了新的项目级 skill，就忘记把它纳入初始化保护边界。
- 不要一次性盲目替换所有相似字符串。
- 不要在未确认项目事实前修改包名、模块名或服务名。
- 不要初始化完不检查残留、不更新约束文档。
