# 项目初始化交付物

当实际执行项目初始化时，推荐至少产出以下交付物。

## 1. 初始化事实文档

推荐路径：

```text
docs/项目信息/项目初始化信息.md
```

建议字段：

- 项目中文名、英文名、简称
- 后端包根
- 业务应用模块名
- 业务应用物理目录名
- JDK / Maven / Spring Boot / Spring Cloud / Spring Cloud Alibaba / Node 基线
- MyBatis-Plus、数据库驱动、Nacos 及其他关键中间件版本来源
- 默认数据库、保留环境 profile 与保留数据库类型 profile
- 服务名、配置中心 dataId、数据库名、表名前缀
- 前端标题、前端项目名称、API 前缀
- 保留项与清理项说明
- 文档历史处理策略
- 父 POM `spring-boot-maven-plugin` 是否已配置 `skip`

## 2. 需要同步的约束文档

- `AGENTS.md`
- `code/backend/AGENTS.md`
- `code/frontend/AGENTS.md`
- `docs/规范/AI开发SOP.md`
- `docs/规范/`

如果初始化改变了目录边界、模块命名或默认执行方式，应同步这些文档中的项目事实。

## 3. 变更留痕

至少更新：

- `docs/变更记录/CHANGELOG.md`
- `docs/变更记录/规范变更.md`

如果模块结构或目录边界发生变化，再补：

- `docs/变更记录/架构变更.md`

## 4. 验证结果

推荐至少记录：

- 运行过的命令
- 是否通过
- 依赖兼容性检查结论
- 未执行项及原因
- 剩余需要人工补充的配置

## 5. 初始化启动脚本

验证通过后，在项目根目录创建 `script/` 目录，生成以下可执行脚本：

- `script/start-backend.sh` — 启动后端（使用初始化后的模块名）
- `script/start-frontend.sh` — 启动前端
- `script/start-all.sh` — 并行启动前后端

所有脚本中使用初始化后的真实值（业务模块名、项目中文名等），并确保 `chmod +x`。

脚本生成后必须实际运行验证：前后端服务均可通过对应脚本正常拉起，开发服务可访问。此项为初始化完成的硬性验收条件，未通过则初始化未完成。

## 6. 初始化总结

最终汇报至少包括：

- 替换了哪些项目标识
- 是否同步修改了业务模块物理目录名
- 是否同步修改了共享模块包路径物理目录和 Nacos dataId 文件名
- 删除了哪些示例残留
- 哪些旧文档被保留、归档或重建
- 保留了哪些模板能力
- 更新了哪些文档
- 做了哪些验证
- 剩余风险和待办
