# 模板保护边界

项目初始化时，要把“项目事实”与“模板规则”分开处理。

## 默认受保护的模板规则资产

- `.agents/skills/`
- `.agents/description/`
- `docs/规范/AI开发SOP.md`
- `docs/规范/`

说明：

- 项目级 skill 目录改为按整个 `.agents/skills/` 保护，而不是逐个 skill 枚举。
- 这样后续新增 `multi-model-delivery-loop` 或其他项目级 skill 时，初始化流程不会因为遗漏名单而误改。
- `.agents/description/` 作为 skill 的演示汇报说明目录，也一并视为模板规则说明资产处理。

## 允许修改的范围

仅允许两类修改：

1. 项目事实替换
- 默认业务模块名
- 默认项目名
- 默认数据库 profile
- 启动模块名
- 目录事实和示例标识

2. 与仓库结构强绑定的事实修正
- 物理目录名变化
- 资源目录名变化
- `DataSQL` 示例目录名变化

## 不允许修改的范围

- 不要把真实项目的业务规范写回模板级 skill
- 不要在初始化时随手重写 skill 工作流
- 不要因为某个项目的技术选型，把模板通用约束整体改成该项目私有约束

## 推荐判断法

如果一句规则回答的是“所有后续项目都应该怎么做”，它大概率属于模板规则，不应在某个项目初始化时被改坏。

如果一句内容回答的是“当前这个项目叫什么、模块叫什么、默认连哪个库”，它才属于项目事实，可以被初始化替换。
