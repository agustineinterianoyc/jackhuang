# 前端开发规范

在当前仓库修改 `code/frontend/` 下的正式前端代码时，按本 skill 执行。

## 开始前

先阅读：

- `code/frontend/AGENTS.md`

再确认：

1. 这是正式前端开发，而不是产品原型任务。
2. 改动应该落在页面、组件、store、类型、请求封装还是样式层。
3. 周边文件已经采用什么命名、状态管理和样式组织方式。

默认优先做最小一致性改动，不为了“更完整的架构”主动扩大重构范围。

## 目录落点规则

按以下顺序判断落点：

1. 路由页面：`src/views/`
2. 公共组件：`src/components/`
3. 布局骨架：`src/layout/`
4. 全局状态：`src/stores/`
5. 请求与接口工具：`src/utils/`、`src/types/`
6. 全局样式：`src/assets/`

如果不确定某段逻辑是否值得抽公共组件或公共 store，默认先留在当前页面附近。

## 页面、组件与布局边界

- `views/`
  放页面级容器、页面流程和页面状态
- `components/`
  放可复用的业务组件或通用组件
- `layout/`
  放站点级布局结构，不堆业务页面逻辑

规则：

1. 页面负责组织页面状态、接口调用和交互流程。
2. 组件负责局部展示和局部交互，不承载整页编排。
3. 布局只处理站点壳、菜单、顶部栏和内容区，不顺手塞业务逻辑。

## Vue 3 写法约束

1. 优先使用 Composition API + `<script setup lang="ts">`。
2. 模板里避免写过重的表达式和分支判断。
3. 一段逻辑只有在明显复用或明显影响可读性时，才提取为单独函数或 composable。
4. 不为了“看起来更高级”提前引入新的状态模式或抽象层。

## 状态管理约束

- 跨页面共享、跨组件共享或与导航状态强相关的状态，才考虑进 Pinia。
- 仅当前页面使用的状态，优先保留在页面组件内部。
- 不提前把短生命周期状态抽成全局 store。

## 请求与类型约束

1. 请求统一复用 `src/utils/request.ts`。
2. 响应和分页等公共类型，优先复用 `src/types/api.ts`。
3. 不在页面里散落重复的接口契约结构。
4. 新增请求逻辑时，先看现有封装和周边页面是否已有相同模式。

## 路由与页面标题

1. 新增正式页面时，在 `src/router/index.ts` 中登记路由。
2. 优先补 `meta.title`，保持菜单标签和页面标题可读。
3. 不绕开现有路由守卫和布局约定。

## 样式约束

1. 组件样式优先使用 `<style scoped lang="less">`。
2. 全局样式统一收口到 `src/assets/`。
3. 不在无关文件里顺手改全局样式。
4. 正式前端任务要同时关注桌面和移动端的基本可用性。

## 交付检查项

页面或交互改动后，至少回头检查：

1. 是否有加载态、空态或错误态。
2. 表单、按钮、菜单等交互是否可达且可理解。
3. 是否影响响应式布局。
4. 是否引入明显的可访问性问题，例如缺少标签、焦点不可见、仅靠颜色表达状态。

## 测试与验证

按改动范围选择执行：

- `npm run lint`
- `npm run type-check`
- `npm run build`
- `npm run test:unit`

如果本次改动没有补单测，最终说明里要写清原因和替代验证方式。

## 变更留痕

1. 单一前端模块的小改动，统一更新 `code/frontend/CHANGELOG.md`。
2. 涉及公共规范、跨前后端协作或目录边界变化时，使用 `change-tracking` 更新 `docs/变更记录/`。
3. 如果任务从页面现象或浏览器排查开始，但最终同时修改了 `code/frontend/` 和 `code/backend/`，必须补充使用 `backend-development-standard` 和 `change-tracking`，不能只按前端小改动收尾。
4. 除非用户明确要求本轮只做分析，否则完成前必须执行一次留痕判定；命中记录条件后直接更新文档，不要只回答“需要记录”。

收尾时额外自检：

- 这次是否为了修复页面问题顺手改了后端返回、字段、接口或配置。
- 如果答案是“是”，是否已经把本次任务升级为“前后端联动修复”并补 `docs/变更记录/`。
- 如果只是前端单模块改动，是否已经实际更新 `code/frontend/CHANGELOG.md`，而不是只说“应该记录”。

## 常见错误

- 把原型任务误做进 `code/frontend/`
- 还没确认复用价值，就提前抽公共组件或全局 store
- 页面里散写接口契约和重复请求逻辑
- 只改桌面样式，不看移动端表现
- 只改代码，不做类型检查、构建或留痕
