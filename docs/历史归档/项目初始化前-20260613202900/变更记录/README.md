# 变更记录目录

`docs/变更记录/` 用于记录项目级变更事实，便于后续人工和 AI 回查。

Git 负责保存“改了什么文件”；本目录负责补充“为什么改、影响什么、后续从哪里继续看”。

## 清单总览

| 文件 | 用途 | 排序要求 | 开头清单 |
| --- | --- | --- | --- |
| `CHANGELOG.md` | 项目级摘要 | 时间倒序 | 需要 |
| `需求变更.md` | 需求口径变化明细 | 时间倒序 | 需要 |
| `架构变更.md` | 架构、目录、模块边界调整明细 | 时间倒序 | 需要 |
| `规范变更.md` | 规范、流程、AI 执行规则调整明细 | 时间倒序 | 需要 |
| `bug修复.md` | 项目级或跨模块 Bug 修复明细 | 时间倒序 | 需要 |

前端模块级小改动统一写入 `code/frontend/CHANGELOG.md`；后端模块级小改动统一写入 `code/backend/CHANGELOG.md`，且每条记录必须标明模块名。

## 当前结构

```text
docs/变更记录/
├── README.md
├── CHANGELOG.md
├── 需求变更.md
├── 架构变更.md
├── 规范变更.md
└── bug修复.md
```

## 目录职责

- `CHANGELOG.md`
  记录按时间倒序排列的项目级变更摘要
- `需求变更.md`
  记录需求口径变化
- `架构变更.md`
  记录目录、模块边界和整体结构调整
- `规范变更.md`
  记录公共规范、AI 执行规则和协作方式变化
- `bug修复.md`
  记录项目级或跨模块 Bug 修复

## 规则真源

什么时候写模块 `CHANGELOG.md`，什么时候升级到本目录，统一以：

- `docs/规范/变更记录规范.md`

为准。
