# 需求文档目录

`docs/需求/` 是正式业务需求事实源，只保留真实需求内容，不再放模板骨架。

## 当前结构

```text
docs/需求/
├── 原始需求/
├── 模块总表.md
├── 需求包/
├── 模块/
└── readme.md
```

## 目录职责

1. `原始需求/`
   接收批次化正式需求输入。
2. `模块总表.md`
   统一模块中文名、模块编码、后端目录名和 DataSQL 目录名。
3. `需求包/`
   记录某批需求、某次迭代或某个版本的整体实现计划。
4. `模块/`
   记录业务模块长期演进和数据库留痕索引。

## 与其他目录的关系

- `docs/原型/`
  作为正式原型输入目录，与 `原始需求/` 同批次配对使用
- `docs/原型站点/`
  作为原型站点产出目录，只给人预览，不作为正式需求拆分输入根
- `docs/工作台/`
  作为面向人工阅读的静态工作台，不替代正式事实源
- `code/backend/DataSQL/`
  作为数据库结构、字段、索引、SQL 和变更流水的正式来源

## 规则真源

需求拆分、模块命名、需求包职责和模块目录规则统一以：

- `docs/规范/需求管理规范.md`

为准。

## 模板位置

需求拆分与实现计划模板统一位于：

- `.agents/templates/requirement/`

不要把模板骨架重新放回 `docs/需求/`。
