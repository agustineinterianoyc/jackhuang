# 数据库留痕规范

## 目标

统一数据库结构变更、SQL 调整和 DataSQL 文档留痕要求，确保数据库相关改动可追踪、可回查、可和业务模块对齐。

## 正式来源

数据库结构与 SQL 的正式留痕来源是：

```text
code/backend/DataSQL/
```

需求模块文档只维护索引，不重复维护完整 SQL。

## 必须留痕的动作

出现以下任一动作时，必须同步更新 `DataSQL`：

1. 新增表
2. 修改表
3. 新增字段
4. 修改字段
5. 删除字段
6. 新增索引
7. 修改索引
8. 删除索引
9. 调整表之间的逻辑关联
10. 修改初始化 SQL 或 Mapper SQL 且影响结构、字段或兼容性

## 留痕结构

当前至少维护：

1. `code/backend/DataSQL/业务变更汇总清单.md`
2. 各业务目录下的明细文档，例如 `表设计与变更记录.md`

推荐明细结构：

1. 业务涉及表总览
2. 变更流水总览
3. 单表详细变更记录
4. 附加说明

## 最小留痕要求

每次留痕至少说明：

1. 哪个业务做了本次数据库操作
2. 涉及哪些表
3. 每张表做了什么动作
4. 字段和索引如何变化
5. 与哪张表的哪个字段做逻辑关联
6. 对应 SQL 在当前数据库下如何写

## SQL 方言要求

生成 DDL、初始化 SQL、Mapper SQL 或 DataSQL 中的 SQL 代码块前，先判断当前项目实际数据库类型。

默认判断顺序：

1. 读取 `code/backend/aldemo/src/main/resources/application.yaml`
2. 查看 `spring.profiles.active`
3. 查看 `app.database.platform`
4. 如果启用了数据库 profile，以 `mysql` / `oracle` / `postgresql` 为准

当前脚手架默认仍按 MySQL 处理，除非配置事实发生变化。

## 与需求和后端规范的边界

1. 业务模块命名和目录对齐，以 `docs/需求/模块总表.md` 为准。
2. 后端代码落位，以 `code/backend/AGENTS.md` 和 `backend-development-standard` 为准。
3. 数据库结构、DDL、Mapper SQL、DataSQL 细则，以 `database-schema-standard` 为准。

## 触发 skill

只要涉及表、字段、索引、DDL、初始化 SQL、Mapper SQL 或 DataSQL 留痕，就应使用 `database-schema-standard`。
