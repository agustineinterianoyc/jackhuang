## 2. 评审摘要

### 2.1 本次接口设计目标

- 为 5 个菜单（P01–P05）+ 进度弹窗 + 汇总 + 附件 + 提醒沉淀稳定的接口契约。
- 以业务动作为单位定义接口，每个接口绑定明确的状态前置条件与角色。
- 列表查询统一 `POST /list`，状态推进类接口统一返回最新主状态 + 子状态。
- 列表分页 `pageSize` 限制 ∈ {10, 20, 50, 100}（与原型每页条数下拉一致）。

### 2.2 接口设计结论

- **新增接口**：38 个，编号 `API-101 ~ API-902`。
- **调整接口**：无
- **延用接口**：项目已有的鉴权、文件服务、通知中心相关接口（不在本清单内列举）
- **废弃接口**：无

### 2.3 需要评审确认的关键点

| 评审点 | 推荐方案 | 风险 | 对前后端实现的影响 |
| --- | --- | --- | --- |
| 列表查询是 GET 还是 POST | 统一 `POST /list`，避免 URL 过长（多筛选 + 多 Tab） | RESTful 风格弱化 | 前端封装统一 |
| 文件上传是直接调本模块还是文件服务 | 直接调通用文件服务上传得 `file_id`，再调 API-901 关联到征集 | 文件服务接口未定 | 上传链路 2 段 |
| 一键提醒返回 | 同步返回成功数 / 跳过数（频控） | 大批量提醒响应慢 | 推荐异步队列 + 立即返回 |
| 数据导出方式 | 服务端生成 Excel 直接下载（`text/octet-stream`） | 数据量大时占内存 | 推荐分页流式 |
| 数据导入方式 | 二段式：上传文件得 `file_id` → 解析校验 → 提交入库 | 大文件或部分错误处理 | 前端展示错误清单 |

## 4. 接口详细说明

> 仅展开关键接口；其余接口的请求 / 响应字段以本设计为准，按相同模式生成。

### 4.1 API-101 创建征集（草稿）

- 业务场景：R01 在 P01 新增页保存。
- 请求路径：`POST /api/opinion/survey`
- 调用页面 / 入口：P01 新增页「保存」按钮
- 权限要求：R01
- 状态要求：无（创建后状态置 `DRAFT`）
- 事务 / 一致性要求：单事务；同时写入 survey、survey_module、survey_target、attachment 关联
- 异常说明：`assess_year + name` 在未删除集合内重复 → 业务异常 `OPINION_DUPLICATE_NAME`

#### 请求参数

| 参数位置 | 参数名 | 类型 | 是否必填 | 含义 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| Body | name | string | 是 | 征集名称 | ≤100 字符 | 例「2026年第一轮第一批次意见征集」 |
| Body | assessYear | int | 是 | 考核年份 | 1980–2100 | — |
| Body | unitDeadline | datetime | 是 | 基层截止时间 | > now | `yyyy-MM-dd HH:mm:ss` |
| Body | deptDeadline | datetime | 是 | 专业截止时间 | > unitDeadline | — |
| Body | noticeContent | string | 否 | 通知内容 | ≤1000 字符 | — |
| Body | remark | string | 否 | 备注 | ≤1000 字符 | — |
| Body | targets | array<object> | 是 | 征集对象 | 至少 1 项 | `[{unitId, unitType}]` |
| Body | modules | array<object> | 是 | 征集模块 | 至少 1 项 | `[{moduleCode, moduleAlias, displayOrder, attachments:[fileId,...]}]` |

#### 响应摘要

| 字段名 | 类型 | 含义 | 说明 |
| --- | --- | --- | --- |
| id | long | 征集任务 ID | — |
| status | string | 主状态 | `DRAFT` |
| createdAt | datetime | 创建时间 | — |

## 6. 接口实现约束

> 本节只保留能直接约束前后端实现和联调的接口契约。

### 6.1 不可改变的接口契约

- **接口前缀**：`/api/opinion/`，子路径与子模块编码完全一致。
- **接口编号**：API-101 ～ API-902 不可重命名 / 改路径 / 改方法。
- **统一响应**：沿用 `backend-api` 的 `ApiResponse<T>`（`{code, message, data}`），错误码遵循 `backend-api/ResultCode.java` 扩展（新增 `OPINION_*` 段）。
- **状态推进类接口**返回必须含最新主状态 + 子状态；列表查询响应中的 `statusText` 由后端按映射返回。
- **列表查询**统一 `POST /list`，请求体含 `page` + `pageSize`；响应体含 `total` + `list`；`pageSize ∈ {10,20,50,100}`。
- **路径参数**：征集 ID 为 `{id}`、基层任务 ID 为 `{taskId}`、专业任务 ID 为 `{taskId}`、附件 ID 为 `{id}`。
- **二次确认**：API-103、API-104、API-105、API-107、API-204、API-404、API-503、API-504 等强动作前由前端二次确认；后端保证幂等，不强校验 `confirm` 字段。
- **幂等性**：状态推进类接口若收到与当前状态一致的二次请求，返回当前状态而非报错。
- **权限**：所有接口在 controller 层校验角色 + 数据范围（单位 / 部门），未通过返回 403。
- **零报送**：无对应外部接口，纯定时任务触发；不要把零报送暴露成接口。

### 6.2 前后端联调关注点

- 前端在加载详情后必须根据 `fillStatus` / `auditStatus` / `surveyStatus` 控制按钮可见性；严禁仅靠列表行的状态推断。
- 列表行内进度列点击触发 API-601 / API-602；筛选器变更后必须重发请求。
- 一键提醒 / 单条提醒响应中的 `skipped` 必须在前端展示提示（「X 个 5 分钟内已提醒，本次跳过」）。
- 数据导出走 GET，后端通过 `Content-Disposition` 指定文件名；前端使用 `axios responseType:'blob'`。
- 数据导入：前端先调通用文件服务上传得 `fileId`，再 POST 至 API-704 触发解析，错误清单分页展示后由用户确认入库。
- 附件：前端先调通用文件服务上传得 `fileId`，再调 API-901 关联到征集模块或汇总。
- P02 / P05 已发布查看页通过 API-202 / API-502 的 `adjustedItems` 字段读取「调整后内容」。
