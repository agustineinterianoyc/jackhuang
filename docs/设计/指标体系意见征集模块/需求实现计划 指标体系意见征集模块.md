## 2. 评审摘要

### 2.1 实施目标

- 在保持需求 V2.1 全量菜单与角色边界的前提下，按设计文档中的状态机与数据模型，落地一个可演示、可联调、可端到端跑通的"指标体系意见征集模块"。
- 模块具备：完整流程冒烟、双向退回闭环、零报送、进度查询与提醒、汇总采纳与发布。
- 前端 UI / 文案 / Tab 顺序对齐原型站点（5 个 P 页面 + 进度弹窗 + 汇总页）。

### 2.2 成功标准

- 5 个二级菜单（P01–P05）可通过路由进入并完成各自业务动作。
- 设计说明书 §10 列出的 10 个验收场景全部可在测试环境复现且通过。
- 全部 38 个接口（API-101 ～ API-902）按《接口清单》契约提供，并通过权限 + 状态前置条件校验。
- 13 张 `ad_opinion_*` 表上线，DataSQL 留痕完整。
- 自动化构建：`./mvnw -pl aldemo -am test` 通过；前端 `npm run type-check && npm run build` 通过。

### 2.3 实施结论

- **推荐实施路径**：先夯实数据库与公共能力，再按角色链路（创建 → 基层 → 专业 → 汇总发布）逐步推进。每个阶段端到端联调一次，避免最后集成风险。
- **不建议采用的路径**：
  - 不要先做完所有 CRUD 再统一接状态机：状态机是模块核心，越晚集成越多重写。
  - 不要把"零报送"作为最后一步：它依赖基层任务表与状态机，应在 STEP-004 阶段实现并验证。
  - 不要先做汇总页再做基层 / 专业链路：汇总数据来源于反馈，无法独立验证。
- **主要依赖**：单位 / 部门主数据（外部）、通用文件服务（外部）、通知中心（外部）、项目级 `backend-api` / `backend-core` / `backend-data` 共享模块。
- **主要风险**：
  - 主数据未就绪 → 数据隔离与征集对象勾选阻塞（推荐先以静态字典 mock，预留切换能力）。
  - 文件服务 / 通知中心未就绪 → 附件、提醒、待办阻塞（推荐先打桩，等接口齐再切）。
  - 状态机变更频率高 → 一旦上线再改成本高（要求第一阶段就把状态枚举与动作集合钉死）。

## 3. 范围说明

### 3.1 范围内

- P01–P05 全部页面与字段（与原型一致）
- 设计文档中列出的 13 张表与 38 个接口
- 零报送、双向退回、一键 / 单条提醒
- 汇总发布与导入导出
- 与文件服务 / 通知中心的对接（接口未定时先打桩）

### 3.2 范围外

- 单位 / 部门 / 用户主数据维护
- 角色权限系统的实现（仅消费）
- 一级菜单"工作台、合同签订、指标体系修订、季度考核、年度考核"的业务实现
- 移动端适配
- 数据可视化看板
- 多年度对比分析

### 3.3 默认假设

- 主数据通过 mock 字典先行；待外部接口齐再切换
- 文件 / 通知中心打桩用 console + 内存 stub
- 部门 ↔ 模块映射通过项目内置字典维护（待评审确认）

## 5. 计划前澄清

| 问题 | 当前假设 | 未确认影响 |
| --- | --- | --- |
| 单位 / 部门主数据接入方式 | 先 mock 字典；外部接口就绪后切换 | 切换时需保证 `unit_id` / `department_id` 不变 |
| 通用文件服务接口 | 临时打桩；返回固定 `fileId` | 切换时需要保留兼容路径 |
| 通知中心接口 | 临时打桩；记 console + 写 `action_log` | 切换时仅替换调用层 |
| 部门 ↔ 模块映射 | 项目内字典维护 | 若改为主数据驱动，需迁移字典 |
| 一键提醒频控阈值 | 5 分钟（可配置） | 阈值变化只动配置 |
| 「调整后内容」字段长度 | 1000 字符 | 若客户要求 ≥1000，需要扩到 TEXT |
| 「其他」Tab 字段口径 | 与 SAFETY 完全一致 | 若不同，需要扩 `extra_field` 解析 |
| API-106 是否人工触发 | 推荐自动；保留接口仅作兜底 | 决定汇总页是否有「汇总」按钮 |

## 6. 分阶段实现计划

### STEP-001 数据库基线与公共枚举

- 步骤目标：完成 13 张表的 DDL、初始留痕、枚举常量、基础 DO/Mapper。
- 评审前提：数据库设计说明书已评审通过；表前缀、字段名、索引最终确定。
- 影响面：[后端] [数据库] [文档]
- 关联接口：无
- 关联数据表：`ad_opinion_*` 全部
- 后端任务概览：
  - 落 `code/backend/aldemo/src/main/resources/db/mysql/schema.sql`
  - 在 `code/backend/DataSQL/opinion/` 建立业务子目录与表设计文档；同步更新 `code/backend/DataSQL/业务变更汇总清单.md`
  - 创建枚举常量类（见《数据库设计说明书》§11.3）

- 前端任务概览：无
- 数据库任务概览：建表、索引、字符集 `utf8mb4`
- 验证方式：`./mvnw -pl aldemo -am -DskipTests validate`；本地启动后表自动建立成功

- 零报送（STEP-004 末）。
- 一键提醒频控（STEP-006）。
- 角色越权（每个 STEP 完成时跑一遍）。
- 发布后只读（STEP-007 末）。
