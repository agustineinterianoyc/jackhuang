## 2. 本次目标

- **本次要解决的问题**：把 V2.1 业务需求 + 原型站点 + 4 份设计文档落地为一个可演示、可联调、可端到端跑通的"指标体系意见征集模块"。
- **成功标准**：
  - 5 个二级菜单（P01–P05）可通过路由进入并完成各自业务动作
  - 设计说明书 §10 列出的 10 个验收场景全部可在测试环境复现且通过
  - 全部 38 个接口（API-101 ～ API-902）按《接口清单》契约提供
  - 13 张 `ad_opinion_*` 表上线，DataSQL 留痕完整
  - 自动化构建：`./mvnw -pl aldemo -am test` 通过；前端 `npm run type-check && npm run build` 通过
- **本次交付范围**：
  - 8 个子模块（survey / unit-fill / unit-audit / dept-feedback / dept-audit / progress / summary / attachment）
  - 双向退回 + 零报送 + 一键 / 单条提醒 + 汇总发布全链路
  - Mock 主数据 / 文件服务 / 通知中心打桩，预留切换能力
- **不在本次范围内**：
  - 一级菜单"工作台、合同签订、指标体系修订、季度考核、年度考核"业务实现
  - 单位 / 部门 / 用户主数据维护页面
  - 角色权限系统的实现（仅消费）
  - 移动端适配、可视化看板、多年度对比分析
- **默认假设**：
  - 主数据通过 mock 字典先行；外部接口就绪后切换
  - 文件 / 通知中心打桩用 console + 内存 stub
  - 部门 ↔ 模块映射通过项目内置字典维护
  - 「调整后内容」按 1000 字符落地（VARCHAR(1000)）
  - 「其他」Tab 字段口径与 SAFETY 一致
  - 一键提醒频控阈值 5 分钟（可配置）
  - 同基层单位同一时间仅一人填报，按 `submitted_by` 锁定
  - API-106「汇总」由后端在专业全部审核通过时自动触发，接口仅作兜底
- **待确认问题**：详见本文档 §7
