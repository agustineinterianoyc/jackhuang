# 实现计划 — 指标体系意见征集模块基线包

## 1. 计划前澄清

- 需求包目标：把 V2.1 业务需求 + 原型 + 4 份设计文档落地为可端到端跑通的"指标体系意见征集模块"
- 成功标准：见 README §2
- 使用者或受众：绩效管理员（R01）/ 基层绩效管理员（R02）/ 基层人资部主任（R03）/ 专业绩效联络员（R04）/ 专业部门负责人（R05）
- 本次范围内：见 README §2 交付范围
- 本次范围外：见 README §2 不在范围
- 已知约束：
  - 必须沿用项目级数据库规范（表前缀 `ad_`、逻辑删除 `deleted_flag`、字符集 `utf8mb4`、不建物理外键）
  - 必须沿用项目级前后端工程结构（`code/backend/aldemo/`、`code/frontend/`）
  - 状态机所有推进 / 退回 / 零报送必须经过 `OpinionStateMachine`，禁止 service 直接 update 状态字段
  - 接口前缀 `/api/opinion/`、编号 API-101 ～ API-902 不可改
- 默认假设：见 README §2 默认假设
- 待确认问题：见 README §7（A/B/C 三级跟踪）

## 1.1 设计基线引用

- 对应设计版本：v1.0（commit `2773cb4`）
- 本次主要承接的设计结论：
  - 6 个主状态：`DRAFT` / `WAIT_FILL` / `FILLING` / `DEPT_FEEDBACK` / `DONE` / `PUBLISHED`
  - 4 套子状态：基层填报、基层审核、专业提交、专业审核
  - 5 个 Tab：`KPI` / `BONUS` / `PARTY` / `SAFETY` / `OTHER`
  - 13 张 `ad_opinion_*` 表 + 三栏枚举映射（后端常量 ↔ 原型 key ↔ 中文展示）
  - 38 个接口契约（API-101 ～ API-902）+ 列表统一 `POST /list`、分页 `pageSize ∈ {10,20,50,100}`
  - 双向退回（R03/R01 → R02、R05/R01 → R04）+ 零报送 + 一键 / 单条提醒 + 5 分钟频控
  - 「待发布」改为 DONE 主状态下的发布汇总页 UI 子状态，不单独建主状态
  - API-106 推荐自动触发；保留接口作兜底
- 尚未定稿但允许带默认假设推进的点：见 README §7（B 类、C 类）
