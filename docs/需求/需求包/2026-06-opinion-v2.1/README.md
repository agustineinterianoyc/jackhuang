## 需求目标

在保持需求 V2.1 全量菜单与角色边界的前提下，按设计文档中的状态机与数据模型，落地一个可演示、可联调、可端到端跑通的「指标体系意见征集模块」。

## 成功标准

- 5 个二级菜单（P01–P05）可通过路由进入并完成各自业务动作。
- 设计说明书 §10 列出的 10 个验收场景全部可在测试环境复现且通过。
- 全部 38 个接口（API-101 ~ API-902）按《接口清单》契约提供，并通过权限 + 状态前置条件校验。
- 13 张 `ad_opinion_*` 表上线，DataSQL 留痕完整。
- 自动化构建通过：`./mvnw -pl aldemohk -am test`；前端 `npm run type-check && npm run build`。

## 范围内

- P01–P05 全部页面与字段（与原型一致）
- 13 张表与 38 个接口
- 零报送、双向退回、一键 / 单条提醒
- 汇总发布与导入导出
- 与文件服务 / 通知中心的对接（接口未定时先打桩）

## 范围外

- 单位 / 部门 / 用户主数据维护
- 角色权限系统的实现（仅消费）
- 一级菜单「工作台、合同签订、指标体系修订、季度考核、年度考核」的业务实现
- 移动端适配
- 数据可视化看板
- 多年度对比分析

## 约束

- 主状态共 6 个，禁止再增加「待发布」主状态
- 基层退回仅在主状态 `FILLING` 时允许；专业退回仅在 `DEPT_FEEDBACK` 且 `PUBLISHED` 前允许
- 「开启专业反馈」前置必须是「全部基层已审核通过」
- 发布后所有写操作禁用
- 基层截止时间到达后系统必须自动空提交并自动审核通过
- 删除统一逻辑删除（`deleted_flag`）
- 表前缀统一 `ad_opinion_`
- 状态字段统一 `VARCHAR(32)`，使用枚举常量类
- 接口前缀 `/api/opinion/...`
- 列表查询统一 `POST /list`，分页字段 `page/pageSize` ∈ {10,20,50,100}

## 假设

- 单位、部门、用户、角色等主数据由系统其他模块或外部主数据系统提供，本模块只读引用（当前以 mock 字典 `OpinionMockMasterDataProvider` 先行）
- 文件上传 / 下载走项目通用文件服务（当前以 `OpinionAttachmentMockController` 打桩）
- 项目时区为 `Asia/Shanghai`，所有时间字段精确到秒
- 列表排序默认按 `创建时间 DESC`
- 提交动作均「先保存再提交」
- 单行文本限制 50 字、多行文本限制 260 字；调整后内容默认 1000 字
- 多轮次通过新建征集任务承载，不引入 `round/batch` 字段
